> **한 문장 요약**: Anthropic과 HHMI Janelia가 AI 에이전트가 실험실·제조 장비를 공통 인터페이스로 발견하고 제어하도록 하는 Model Hardware Standard 연구 프리뷰를 공개했다.

## 무엇이 발표됐나

Anthropic과 HHMI Janelia는 8월 27일 **Model Hardware Standard(MHS)** 연구 프리뷰를 발표했다. 서로 다른 현미경, 액체 처리기, 로봇 팔과 센서를 에이전트가 같은 방식으로 발견·조정하는 장비 계층이다. 모델과 에이전트 하네스에 종속되지 않고 MCP, CLI와 코드 파일로 접근할 수 있다. 다만 발표 당시에는 일부 과학 연구소·제조사만 참여하는 프리뷰였고, 공개 사양과 오픈소스 코드는 안전 평가 뒤 제공할 계획이었다.

## 공통 명령보다 상태와 한도가 중요하다

각 MHS 드라이버는 온도 읽기나 설정값 쓰기 같은 단순 `read`·`write` 원시 명령을 장비별 API로 번역한다. 여기에 장비가 될 수 있는 상태와 수행 가능한 절차, 무게·측정 범위처럼 코드만으로 알기 어려운 특성, 강제할 안전 한도를 기계가 읽는 명세로 노출한다. 운영자는 자연어 태그를 직접 쓰거나 에이전트의 인터뷰로 채울 수 있다. 에이전트는 이 명세를 바탕으로 여러 장비의 순서를 계획하고 상태를 관찰하며 매개변수를 바꾼다. 빠르거나 오래 걸리는 작업은 매 단계 모델 호출에 맡기지 않고 드라이버 명령을 코드 파일로 묶어 장비 쪽에서 실행한다.

Genentech의 단백질 정량 실험에서는 Claude가 액체 처리기·로봇 팔·판독기를 한 흐름으로 조정했다. 처음에는 물과 점성 단백질 용액에 같은 유속을 써 거품과 오차를 만들었지만, 전문가가 물리적 원인을 설명한 뒤 유속과 혼합 절차를 다시 탐색했고 교훈을 재사용 가능한 스킬로 저장했다. 이는 폐루프 최적화 가능성과 함께, 모델이 소프트웨어 오류와 거품 같은 물리 실패를 스스로 구분하지 못할 수 있다는 한계를 동시에 보여준다.

## 개발자에게 왜 중요한가

MHS는 도구 호출을 웹 API에서 실제 장비로 확장한다. 이때 드라이버는 편의용 어댑터가 아니라 안전 경계가 된다. 단위와 좌표계, 허용 상태 전이, 속도·온도 상한, 충돌 방지와 긴급 정지를 모델 프롬프트가 아닌 로컬 제어기가 강제해야 한다. 각 명령에는 멱등성, 타임아웃, 취소와 보상 동작을 정의하고, 에이전트 계획·센서 관측·사람 승인·실제 장비 상태를 함께 기록해야 재현과 사고 분석이 가능하다.

## 한계와 검증 포인트

통합 기간을 수개월에서 수시간으로 줄였다는 수치는 초기 파트너 사례이며 독립 비교가 아니다. MHS는 프로그래밍 인터페이스가 없는 장비를 아직 직접 지원하지 않고, 장비별 드라이버 품질과 제조사 펌웨어의 안전 기능에 의존한다. 모델의 공간·물리 추론도 불완전해 전문가 감독이 필요하다. 도입 전에는 통신 단절·센서 이상·잘못된 단위·동시 명령을 주입해 안전 상태로 멈추는지, 권한 없는 쓰기가 차단되는지, 모델을 바꿔도 같은 프로토콜과 인터록이 유지되는지를 실제 하드웨어 인더루프에서 평가해야 한다.
